# 🚀 Каскадный VPN на AmneziaWG 3.1 — пошаговое руководство

Готовое решение для развёртывания **каскадного VPN** (двойной туннель) между двумя серверами VPS с обфускацией протокола AmneziaWG 3.1. К проекту прилагается **Web-панель** для управления клиентами, статистикой и переключением серверов.

Клиент подключается к **первому серверу** (SERVER-A, обычно в стране с блокировками), трафик идёт через **второй сервер** (SERVER-B, в свободной стране) и только потом выходит в открытый интернет. Оба плеча туннеля защищены шифрованием и обфускацией, устойчивой к DPI/ТСПУ.

### Что даёт этот проект:
- ✅ Обход блокировок и DPI с помощью протокола AmneziaWG 3.1
- ✅ Двойной каскад — скрывает факт использования зарубежного VPN
- ✅ Уникальные параметры обфускации для каждого клиента (маскировка под DNS)
- ✅ Удобная **Web-панель** с авторизацией
- ✅ Автоматические скрипты управления (добавить/удалить/посмотреть статистику)
- ✅ Генерация `vpn://` ссылок и QR-кодов для приложения AmneziaVPN
- ✅ Telegram-уведомления о состоянии туннелей

## 🚀 Установка и Обновление (Быстрый старт)

Для тех, кто хочет развернуть всё максимально быстро. Скрипт сам установит зависимости, настроит ключи, поднимет интерфейсы, добавит cron-задачи и развернёт веб-панель.

### 📥 Первичная автоматическая установка

Выполняется **только на SERVER-A (входном)** от пользователя `root`:
```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/daff4ik/amneziawg-cascade/main/deploy.sh -o /tmp/deploy.sh >/dev/null; cat /tmp/deploy.sh)"
```
Скрипт интерактивно запросит:
- IP-адреса обоих серверов.
- SSH-пароль от SERVER-B (используется один раз для удалённой настройки через туннель).
- Имя сервера и согласие на установку веб-панели.

### 🔄 Обновление конфигурации и Web-панели по SSH

Если вышли новые функции или веб-панель обновилась, вы можете накатить апдейт без пересоздания ключей и без сброса настроек SERVER-B. Выполните на **SERVER-A**:
```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/daff4ik/amneziawg-cascade/main/deploy.sh)" -- --update
```
*Этот режим обновит только вспомогательные скрипты управления, логику сборщика трафика и саму веб-панель.*

## 🏗 Архитектура и Требования

**Требуются два VPS-сервера** с Ubuntu 22.04 / Debian 12 или новее:
*   `RAM: от 512 МБ` | `vCPU: 1` | `Диск: 5 ГБ`
*   Серверы должны **пинговать друг друга** напрямую (открытые порты UDP, без NAT-проблем).

```text
┌────────┐      ┌─────────────────┐      ┌──────────────────┐      ┌──────────┐
│ Client │ ───► │  SERVER-A       │ ───► │  SERVER-B        │ ───► │ Internet │
│ (Amnz) │      │  (страна X)     │      │  (страна Y)      │      │          │
└────────┘ UDP  │  awg1 → awg0    │ UDP  │  awg0 → NAT      │      └──────────┘
          :585  └─────────────────┘ :8443└──────────────────┘
```

- **SERVER-A** — «входная точка». Слушает клиентов на порту **585/udp**.
- **SERVER-B** — «выходная точка». Слушает туннель от A на порту **8443/udp**.
- Между ними — **шифрованный туннель awg0** (внутренние IP `10.10.10.1` и `10.10.10.2`).
- Клиенты получают внутренние IP из подсети **10.8.0.0/24**.

## 📱 Какое приложение использовать на клиенте

Проект требует использования приложений, поддерживающих протокол **AmneziaWG**:

1. **[AmneziaVPN](https://amnezia.org/ru/downloads)** *(Рекомендуется)* — универсальное приложение (Windows, macOS, Linux, Android, iOS). Поддерживает импорт `vpn://` ссылок и QR-кодов.
2. **[AmneziaWG](https://github.com/amnezia-vpn/amneziawg-go/releases)** — лёгкое приложение только под данный протокол. Подходит для слабых устройств (`.conf` файлы).

> **Важно:** Обычный клиент WireGuard работать **не будет**, так как не умеет применять параметры обфускации.

## 📦 Управление клиентами (CLI скрипты)

Если вы предпочитаете командную строку, в `/usr/local/bin/` доступны скрипты:

- **Добавить клиента:** `sudo amnezia-add-client.sh <имя>`
- **Удалить клиента:** `sudo amnezia-remove-client.sh <имя>` (без имени откроет меню)
- **Список клиентов:** `sudo amnezia-list-clients.sh`
- **Настройка Telegram-бота:** `sudo amnezia-notify-setup.sh`

## 🐛 Диагностика и Troubleshooting

### Медленная скорость / upload 0 (Потеря пакетов)
Обычно это проблема с MTU/MSS (фрагментация пакетов). **Важное правило:** MTU клиента не должен превышать MTU серверных туннелей, иначе пакеты будут дропаться.

**Решение:**
1. На **обоих** серверах для туннельного интерфейса `awg0` должно быть установлено `MTU = 1180`.
2. **Только на SERVER-A** (входном) для клиентского интерфейса `awg1` должно быть `MTU = 1100`.
3. В приложении **на клиенте** (или в `.conf` файле) установите `MTU = 1100` (или `1080`). *Если у клиента стоит 1280 (по умолчанию) — скорость может падать до нуля.*
4. Убедитесь, что настроен MSS-клэмп `--set-mss 1000` на обоих серверах (добавляется автоматически скриптом `deploy.sh` в правила PostUp/PostDown).
5. Проверьте, что параметр `RandomTrailers` на клиенте и в интерфейсе `awg1` (SERVER-A) **совпадает** (обычно `= on`).

### Туннель awg0 не поднимается
Проверьте логи и рукопожатия:
```bash
sudo journalctl -xeu awg-quick@awg0 -n 50 --no-pager
sudo awg show awg0
```
Частые причины:
- Не совпадают `HeaderProtectionKey`, `S1-S4`, `H1-H4` на SERVER-A и SERVER-B.
- Не совпадают `RandomTrailers` (в рамках туннеля awg0 они должны быть одинаковыми, обычно `off`).
- Порт 8443/udp заблокирован у провайдера SERVER-B.

### Клиент подключается, но нет интернета
Проверьте на SERVER-A (маршрутизацию):
```bash
ip rule show               # должно быть from 10.8.0.0/24 lookup 100
ip route show table 100    # должно быть default dev awg0
```
Проверьте на SERVER-B (NAT):
```bash
sudo iptables -t nat -L POSTROUTING -n -v    # MASQUERADE должен присутствовать
```

## 📖 Базовые вопросы для новичков

<details>
<summary><b>Что такое SSH и где взять данные для подключения?</b></summary>

**SSH** — это защищенный способ управлять сервером удалённо. Сразу после оплаты VPS провайдер присылает на вашу электронную почту письмо с IP-адресом, логином (обычно `root`) и паролем. Вы используете эти данные в терминале (macOS/Linux) или в программах вроде PuTTY/MobaXterm (Windows):
`ssh root@123.45.67.89`
</details>

<details>
<summary><b>Что такое «свой VPN» и зачем он нужен?</b></summary>

Обычный платный VPN — это чужая инфраструктура. Свой (self-hosted) VPN — это сервер, который принадлежит только вам. Никто не пишет логи, никто не режет вам скорость, и вы полностью контролируете свои данные.
</details>

<details>
<summary><b>Почему нужны именно два сервера (каскад)?</b></summary>

Если сервер находится за рубежом, системы блокировки (ТСПУ) со временем могут заметить VPN-трафик и заблокировать соединение. Если сервер в России — он подвержен локальным блокировкам сайтов.
Каскад решает это: вы подключаетесь к российскому серверу (что не вызывает подозрений), а он скрытно перенаправляет ваш трафик на зарубежный сервер, откуда вы уже безопасно выходите в интернет.
</details>
