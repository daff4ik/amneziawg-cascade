# 🚀 Каскадный VPN на AmneziaWG (с Web-панелью и Stealth-режимом)

Готовое решение для развёртывания **каскадного VPN** (двойной туннель) между двумя VPS с обфускацией протокола AmneziaWG 3.1.

Трафик клиента подключается к первому серверу (входному), маршрутизируется по зашифрованному туннелю на второй сервер (выходной, за рубежом) и только оттуда выходит в открытый интернет. Это обеспечивает высочайшую устойчивость к DPI-анализаторам и ТСПУ, полностью скрывая факт использования VPN.

В комплект входит **Web-панель управления**, защищенная страницей-заглушкой (Stealth-режим).

## 🏗 Архитектура

```text
┌────────┐      ┌─────────────────┐      ┌──────────────────┐      ┌──────────┐
│ Client │ ───► │  SERVER-A (RU)  │ ───► │  SERVER-B (DE)   │ ───► │ Internet │
│ (Amnz) │      │  Web-Panel      │      │  (Выходной узел) │      │          │
└────────┘ UDP  │  awg1 → awg0    │ UDP  │  awg0 → NAT      │      └──────────┘
          :585  └─────────────────┘ :8443└──────────────────┘
```

## ✨ Возможности

*   **Надежный обход блокировок:** Использование протокола AmneziaWG + разрыв соединения (каскад) между странами.
*   **Web-панель (FastAPI):** Управление пользователями, статистика в реальном времени, скачивание конфигов.
*   **Stealth-режим (Заглушка):** Панель скрывается за ретро-заглушкой (Nginx) на вашем домене. Сканеры и боты видят только "сайт в разработке".
*   **Динамическое управление серверами:** Переключайте выходной SERVER-B прямо из браузера. Скрипт сам зайдет по SSH, установит зависимости и поднимет новый шлюз.
*   **Отказоустойчивая установка:** Скрипты автоматически используют зеркала (ghproxy) при недоступности GitHub.
*   **Внутрисетевая связь (LAN):** Возможность прямо из веб-панели объединить клиентов в виртуальную локальную сеть (полезно для обмена файлами, RDP, сетевых дисков).

## 🚀 Установка (Быстрый старт)

Для установки системы на чистый сервер выполните команду загрузки и запуска основного скрипта на **входном сервере (SERVER-A)**.
*(Требуются права `root` и установленная ОС Ubuntu 22.04 / Debian 12).*

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/daff4ik/amneziawg-cascade/main/deploy.sh -o /tmp/deploy.sh >/dev/null; cat /tmp/deploy.sh)"
```

Скрипт интерактивно запросит:
1. IP-адреса обоих серверов.
2. SSH-пароль от SERVER-B (используется единоразово).
3. Разрешение на установку Web-панели.

После успешной установки веб-панель будет доступна напрямую по вашему **IP-адресу на порту 8000** (например, `https://123.45.67.89:8000`). Сразу после этого скрипт предложит вам усилить безопасность и спрятать панель (Stealth-режим).

## 🛡️ Защита веб-панели (Stealth-режим)

Для защиты от цензоров и сканеров панель можно перевести в **Stealth-режим**. При переходе на ваш IP или домен будет открываться безобидная страница-заглушка "Сайт в разработке". Доступ к панели откроется только при дописывании вашего личного секретного кодового слова в URL.

**Требование:** У вас должен быть домен или субдомен (например, `mysite.com`), А-запись которого направлена на IP-адрес SERVER-A.
*(Если у вас нет домена, вы можете получить его абсолютно бесплатно на сайте [FreeDNS](https://freedns.afraid.org/)).*

Если вы пропустили установку Stealth-режима при развертывании, вы можете активировать его вручную в любой момент:
```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/daff4ik/amneziawg-cascade/main/stealth-setup.sh)"
```
* Пример доступа после настройки: `https://mysite.com/кодовое_слово/`

### Аварийное управление доступом
Если у вас отвалился домен или возникли проблемы с Nginx, вы можете временно вернуть прямой доступ к панели по IP (порт 8000) через консольную утилиту:
* `sudo amnezia-panel-access.sh on` — Включить прямой IP-доступ (Stealth-режим отключен).
* `sudo amnezia-panel-access.sh off` — Вернуть панель под защиту Nginx и закрыть внешний IP.

## 🔄 Обновление компонентов

Веб-панель поддерживает встроенную проверку новых версий из этого репозитория. Чтобы обновить скрипты управления и саму веб-панель **без затрагивания конфигураций пользователей и туннеля**, используйте ключ `--update`:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/daff4ik/amneziawg-cascade/main/deploy.sh)" -- --update
```

## ⚙️ Управление через CLI (Консоль)

Все функции веб-панели доступны системным администраторам напрямую из консоли сервера:

* **Добавление клиента:** `sudo amnezia-add-client.sh <имя>`
* **Удаление клиента:** `sudo amnezia-remove-client.sh <имя>`
* **Список клиентов и статистика:** `sudo amnezia-list-clients.sh`
* **Ручной Healthcheck туннеля:** `sudo amnezia-healthcheck.sh`
* **Настройка уведомлений Telegram:** `sudo amnezia-notify-setup.sh`

## 📱 Клиентские приложения

Сгенерированные файлы (`.conf` и `vpn://` ссылки) предназначены для следующих приложений:
* **AmneziaVPN** (Рекомендуется) — поддерживает все платформы, умеет импортировать `vpn://`.
* **AmneziaWG** (Легкий клиент) — официальный форк WireGuard с поддержкой обфускации. Используйте классические `.conf` файлы.

> **Важно:** Стандартный клиент WireGuard **не сможет** подключиться к этому серверу, так как не поддерживает параметры обфускации (Jc, S1, H1 и т.д.).

## 🐛 Диагностика и FAQ

**Панель не запускается или недоступна:**
Проверьте статус службы панели и логи ошибок:
```bash
sudo systemctl status amnezia-panel
sudo journalctl -u amnezia-panel -n 30
```
Если используется Stealth-режим, убедитесь, что Nginx работает: `sudo systemctl status nginx`.

**Клиент подключается, но интернета нет:**
Проверьте, не блокирует ли провайдер SERVER-B (выходной узел). На SERVER-A выполните:
```bash
ping -c 3 10.10.10.1
```
Если пинг не проходит, туннель между серверами разорван. Воспользуйтесь Healthcheck-скриптом или перезапустите туннели через веб-панель.

**Низкая скорость, не прогружаются картинки или зависает соединение:**
Это классическая проблема фрагментации пакетов. Убедитесь, что MTU клиента (в клиентском приложении) равен **1280** или ниже, в то время как MTU туннеля `awg1` на входном сервере составляет **1100**. Скрипт `deploy.sh` автоматически прописывает нужные правила MSS Clamping для избежания этих проблем, однако на некоторых устройствах может потребоваться ручное снижение MTU в настройках подключения (например, до 1100).
